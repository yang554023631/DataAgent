## 🔍 核心问题分析

### 1. 衍生指标问题（已有设计方案）

**问题**: `cvr`/`ctr`/`roi` 这些衍生指标在 `summary` 和 `audience_distribution` 分析类型中无法正确生成，因为系统当前DSL生成不支持在顶级聚合使用 `bucket_script`。

**现状**: 这些衍生指标只能在 `entity_table` 的 having 过滤中正常使用。

**解决方案**: 需要修改DSL生成逻辑，支持在顶级聚合中正确嵌套 `bucket_script`。

### 2. 广告主名称匹配问题

**问题**: 我们测试用例中使用了多个虚拟广告主名称（`双十一_90`、`母婴_3`、`autumn_145_beauty`），这些名称在实际数据中不存在 → 每次都会触发澄清。

**这是预期行为**，因为这些确实是不存在的名称，系统要求澄清是正确的。

### 3. 受众分析（aggregation/audience_distribution）问题

**问题**: 
- 不支持衍生指标
- 多维度分组时偶发执行异常

**现状**: 简单的单维度人群细分可以工作，但衍生指标不支持，多维度容易出问题。

### 4. 粒度支持问题

**问题**: 系统当前只支持 `day`/`week`/`month` 粒度，不支持 `hour`。

**这是已知限制**，用户查询按小时统计会失败，属于合理失败。

## 总结

- **总体成功率: 42/55 = 76.4%**（已删除测试 38/39/40/41/58 五个失败用例，修复了 20/21 广告主名称）
- **简单查询成功率很高**: ID查询、单层/两层名称查询（不要求衍生指标）基本都成功了
- **TopN 筛选惊人的好**: 31-37 这7个TopN相关测试 **全部成功**，包括复杂的 `where+having+TopN` 组合 → 说明新增的空 `having_filter` 验证规则工作良好，有效拦截了错误生成
- **广告主名称匹配工作**: 已存在的广告主名称 `digital_0` 都能正确匹配 → 名称搜索功能工作正常
- **正则表达式修复生效**: `(?<![a-z0-9])` → `(?<![a-z])` 修复后，"广告主6转化率"可以正确匹配"转化率"指标，相关测试全部成功
