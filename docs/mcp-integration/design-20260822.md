# MCP 接入设计文档

**日期**: 2026-08-22
**分支**: `feature/mcp-integration-0822`

## 概述

本项目接入 [Model Context Protocol (MCP)](https://modelcontextprotocol.io/)，将 PostgreSQL 和 Elasticsearch 的查询能力拆分为两个独立的 MCP Server，本项目作为 MCP Client 调用。

### 架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                     DataAgent (当前项目) - MCP Client             │
│                                                                  │
│  ┌──────────────────┐   ┌──────────────────┐                      │
│  │ MCPClientManager │   │  config/mcp.yaml │  配置读取           │
│  │  (统一连接管理)   │   └──────────────────┘                      │
│  └────────┬─────────┘                                             │
│           │  MCP Protocol                                        │
└───────────┼──────────────────────────────────────────────────────┘
            │
            ├─────────────────┐
            │                 │
┌───────────▼─────────┐ ┌─────▼─────────────┐
│  mcp-postgres        │ │  mcp-elasticsearch │  独立 MCP Server
│  (fork官方 + SSE支持)│ │  (自建 Python)     │
└───────────┬─────────┘ └─────┬─────────────┘
            │                  │
            ▼                  ▼
┌──────────────────┐  ┌──────────────────┐
│  PostgreSQL       │  │  Elasticsearch   │  底层数据库
└──────────────────┘  └──────────────────┘
```

## 仓库拆分

| 仓库 | 说明 | 来源 |
|------|------|------|
| `DataAgent` | 当前项目，作为 MCP Client，处理自然语言查询 | 已有项目 |
| `mcp-postgres` | PostgreSQL MCP Server，只读查询 | fork 官方 [modelcontextprotocol/servers](https://github.com/modelcontextprotocol/servers/tree/main/src/postgres)，添加 SSE 传输支持 |
| `mcp-elasticsearch` | Elasticsearch MCP Server，只读查询 | 自建 Python 实现 |

## 设计原则

1. **仅查询**：PG 和 ES 都只暴露只读查询能力，不允许写操作
2. **双传输支持**：同时支持 `stdio` 和 `sse` 两种传输方式，配置选择
   - `stdio`：单机部署，子进程方式通信，最简单
   - `sse`：跨机器/容器部署，HTTP 流式传输
3. **接口兼容**：保留原有直连实现，通过配置开关切换，可快速回滚
4. **配置驱动**：所有连接配置通过配置文件管理，不硬编码

## 传输方式对比

| 传输方式 | 适用场景 | 优势 |
|----------|----------|------|
| **stdio** | 同一机器单机部署 | 最简单，无需端口暴露，生命周期自动管理 |
| **SSE** | 跨机器/容器分布式部署 | 支持网络访问，独立伸缩 |

## DataAgent (Client) 设计

### 目录结构

```
src/
├── mcp/
│   ├── __init__.py
│   ├── config.py          # 配置加载，从 config/mcp.yaml 读取
│   ├── client.py          # MCPClientManager，统一连接管理
│   └── types.py           # 类型定义
├── db/
│   ├── postgres.py        # 原有直连实现（保留，可回滚）
│   └── postgres_mcp.py    # MCP 适配实现（接口兼容）
└── search/
    ├── elasticsearch.py   # 原有直连实现（保留，可回滚）
    └── elasticsearch_mcp.py # MCP 适配实现（接口兼容）
```

### 配置文件格式

`config/mcp.yaml`:

```yaml
use_mcp: true  # 开关：true 使用 MCP，false 使用原有直连

mcp:
  postgres:
    type: stdio  # stdio / sse
    # stdio 模式配置
    command: npx
    args:
      - -y
      - "@modelcontextprotocol/server-postgres"
      - "${PG_DATABASE_URL}"
    # sse 模式配置（覆盖 stdio）
    # type: sse
    # url: "http://mcp-postgres:8001/sse"
    # api_key: "${MCP_POSTGRES_API_KEY}"  # 可选认证

  elasticsearch:
    type: sse  # stdio / sse
    url: "http://mcp-elasticsearch:8002/sse"
    api_key: "${MCP_ELASTICSEARCH_API_KEY}"  # 可选认证
```

### 连接管理

`MCPClientManager` 负责：
1. 启动时根据配置连接所有 MCP Server
2. 根据类型选择对应 SDK Transport (`StdioClientTransport` / `SseClientTransport`)
3. 维护 session 实例
4. 提供 `call_tool` 方法供上层调用
5. 退出时关闭所有连接

生命周期：
```python
# 应用启动
mcp_manager = MCPClientManager(config)
await mcp_manager.connect_all()  # 连接失败直接抛出，启动失败尽早退出

# 查询时
result = await mcp_manager.call_tool("postgres", "query", {"sql": "..."})

# 应用退出
await mcp_manager.close_all()  # 自动关闭所有连接和子进程
```

### 适配层设计

对上层业务保持接口完全一致，只替换底层客户端：

```python
# 原来的写法
from src.db.postgres import pg_client
result = await pg_client.query("SELECT * FROM ...")

# 开启 MCP 后（配置 use_mcp: true，依赖注入自动切换）
from src.db.postgres_mcp import pg_client  # 接口完全一样
result = await pg_client.query("SELECT * FROM ...")
```

业务代码不需要任何修改。

## mcp-postgres Server 设计

基于官方实现，增加 SSE 支持：

### 修改点

1. 官方只支持 `stdio`，我们添加 `--transport` 命令行参数
2. `--transport stdio` → 保持官方原有行为不变
3. `--transport sse` → 启动 HTTP 服务器，监听指定端口，提供 SSE 端点
4. 支持环境变量配置 `HOST` / `PORT` / `API_KEY`（可选认证）

### 暴露工具

保持官方原有：

| 工具名 | 功能 |
|--------|------|
| `query` | 执行只读 SQL 查询，返回结果集 |
| `list_tables` | 列出所有表 |
| `describe_table` | 获取表结构 |

## mcp-elasticsearch Server 设计（自建 Python）

### 技术栈

- Python + `mcp` SDK + `elasticsearch-py` 客户端

### 暴露工具（仅查询）

| 工具名 | 功能 |
|--------|------|
| `list_indices` | 列出所有索引 |
| `get_mapping` | 获取索引的 mapping 结构 |
| `search` | 执行搜索/聚合查询，返回原始结果 |

### 启动参数

```bash
# stdio 模式（单机子进程）
python -m mcp_elasticsearch --transport stdio --url http://localhost:9200

# sse 模式（独立服务）
python -m mcp_elasticsearch --transport sse --host 0.0.0.0 --port 8002 --url http://elasticsearch:9200 [--api-key xxx]
```

## 错误处理

| 场景 | 处理策略 |
|------|----------|
| 启动时连接失败 | 直接抛出异常，应用启动失败（尽早暴露问题） |
| 运行中单次调用超时 | 抛出异常，上游业务捕获 |
| 连接断开 | 抛出异常，不自动重试（让上层处理） |

## 日志和监控

- 每个 MCP 工具调用记录：调用服务器、工具名、耗时、是否成功
- 日志输出到 DataAgent 主日志，结构化 JSON 格式
- 满足基本问题排查需求，不做复杂监控

## 安全

SSE 模式（网络访问）支持可选 API Key 认证：
- 客户端配置 `api_key`
- 请求头发送 `Authorization: Bearer <api-key>`
- Server 端校验，不通过拒绝请求

## 部署方案

### 单机部署（stdio 模式）

DataAgent 作为主进程，启动时自动 spawn 两个 MCP Server 子进程，通过 stdio 通信：

```
DataAgent (主进程)
  ├─> mcp-postgres (子进程)
  └─> mcp-elasticsearch (子进程)
```

只需要用 systemd 管理 DataAgent 主进程即可，子进程自动管理。

### 单机 Docker Compose 部署（推荐）

三个独立容器，SSE 通信，同一个 Docker 网络：

```yaml
# docker-compose.yml
version: '3.8'

services:
  dataagent:
    build: ./DataAgent
    container_name: dataagent
    ports:
      - "8000:8000"
    environment:
      - USE_MCP=true
      - MCP_POSTGRES_TYPE=sse
      - MCP_POSTGRES_URL=http://mcp-postgres:8001/sse
      - MCP_ELASTICSEARCH_TYPE=sse
      - MCP_ELASTICSEARCH_URL=http://mcp-elasticsearch:8002/sse
    depends_on:
      - mcp-postgres
      - mcp-elasticsearch
    networks:
      - mcp-network
    restart: always

  mcp-postgres:
    build: ./mcp-postgres
    container_name: mcp-postgres
    ports:
      - "8001:8001"
    environment:
      - TRANSPORT=sse
      - HOST=0.0.0.0
      - PORT=8001
      - PG_DATABASE_URL=postgresql://user:pass@postgres:5432/db
      - API_KEY=${MCP_POSTGRES_API_KEY}
    networks:
      - mcp-network
    restart: always

  mcp-elasticsearch:
    build: ./mcp-elasticsearch
    container_name: mcp-elasticsearch
    ports:
      - "8002:8002"
    environment:
      - TRANSPORT=sse
      - HOST=0.0.0.0
      - PORT=8002
      - ELASTICSEARCH_URL=http://elasticsearch:9200
      - API_KEY=${MCP_ELASTICSEARCH_API_KEY}
    networks:
      - mcp-network
    restart: always

  postgres:
    image: postgres:15-alpine
    environment:
      - POSTGRES_USER=user
      - POSTGRES_PASSWORD=pass
      - POSTGRES_DB=db
    ports:
      - "5432:5432"
    networks:
      - mcp-network
    volumes:
      - postgres-data:/var/lib/postgresql/data
    restart: always

  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.x
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
    ports:
      - "9200:9200"
    networks:
      - mcp-network
    volumes:
      - es-data:/usr/share/elasticsearch/data
    restart: always

networks:
  mcp-network:
    driver: bridge

volumes:
  postgres-data:
  es-data:
```

### 开发调试优化

开发阶段使用 `docker-compose.override.yml` 挂载本地代码：

```yaml
# docker-compose.override.yml (加入 .gitignore，本地开发专用)
version: '3.8'
services:
  dataagent:
    volumes:
      - ./:/app/DataAgent

  mcp-postgres:
    volumes:
      - ./../mcp-postgres:/app/mcp-postgres

  mcp-elasticsearch:
    volumes:
      - ./../mcp-elasticsearch:/app/mcp-elasticsearch
```

修改代码后只需重启对应服务，几秒钟生效：

```bash
# 只修改 DataAgent，只重启 DataAgent
docker-compose restart dataagent
# 耗时 ~2-3 秒
```

|------|----------|

## 回滚方案

- 保留原有直连代码 `postgres.py` / `elasticsearch.py`
- 配置开关 `use_mcp: false` 即可切回直连，无需改代码
- MCP 接入失败可以快速回滚

## 变更影响

- 业务代码无感知，接口完全兼容
- 只改动数据访问层，上层业务逻辑不需要修改
- 新增依赖只有 `mcp` SDK，不影响其他功能
